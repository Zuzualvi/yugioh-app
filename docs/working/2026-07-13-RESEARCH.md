# Research Brief — Yu-Gi-Oh! Edison Duel App

**Date:** 2026-07-13 · **Owner:** Product Lead. Consolidates four research slices for a technical audience not present in the product conversation. Full deep-dives (with inline citations) are the companion files referenced per section.

---

## 1. What we're building

A browser-based, responsive (desktop + mobile), **rules-enforcing** Yu-Gi-Oh duel simulator + deck builder for a **private, non-commercial group** (the founder + a few friends), scoped to the retro **Edison format**. Strategy: **reuse a proven open-source rules engine and build a fresh modern UI on top** — the market gap is UX + Edison focus + mobile, not engine correctness. Teaching features (an in-duel "why?" chatbot) and a native app are explicitly V2+.

## 2. Edison format (grounding for legality + rules)
*Deep dive: `…-research-edison-format.md`.*

- **Definition:** the **March 2010 TCG** competitive environment (named after the SJC in Edison, NJ). **Correction to a common misconception:** the pool runs **up to & including Duelist Pack: Kaiba (2010-04-20)** and **excludes The Shining Darkness** (TSHD is the set that *ended* the format) and everything later. Last Core Booster = Absolute Powerforce.
- **Banlist:** the **March 2010 TCG Forbidden & Limited List** — **43 Forbidden / 70 Limited / 19 Semi**. Copy caps apply across Main+Extra+Side combined: Forbidden 0 / Limited 1 / Semi 2 / else 3.
- **In-window exclusion (resolved):** the carve-out is **27 Duel Terminal 1 (DT01, Jan 2010) cards, NOT Hidden Arsenal** — all 30 Hidden Arsenal 1 cards are legal. (Konami policy: Duel Terminal cards aren't tournament-legal until reprinted via booster/deck; these came via TSHD or later.) Cross-verified vs edisonformat.net `EdisonCards.json` + the EDOPro Edison whitelist. See `…-research-edison-pool-exclusions.md`.
- **Deck construction:** Main 40–60; Extra 0–15 (**Fusion + Synchro only**); Side **0–15** (not "exactly 15"). Who-goes-first = **winner of the toss chooses** play/draw.
- **Mechanics in-era:** Normal/Effect/Ritual/Fusion + **Synchro & Tuners**, plus Gemini/Union/Spirit/Flip. **No Xyz (2011), Pendulum (2014), or Link (2017)** — a simpler board than modern.
- **Pool size:** ≈ **3,681 unique cards** (edisonformat.net) / ≈ 3,671 (EDOPro whitelist); the common "~4,500" figure is wrong. ~12-card delta (tokens/anime-promos) = founder decides at sign-off.
- **Era rules that differ from modern (a correctness checklist):** ignition-effect **priority** IN effect; **first player draws turn 1** (but no Battle Phase on turn 1); pre-2014 damage-step timing; pre-MR3 single-Field-Spell (new destroys old). See §5.
- **Anchor source:** `edisonformat.net` (the group's own tool), cross-checked against Yugipedia (Konami's archived March 2010 list), Format Library, ygoprodeck, goatworld.

## 3. Engine, data & image ecosystem
*Deep dive: `…-research-engine-landscape.md`.*

- **One dominant engine:** `ocgcore`/`ygopro-core` (C++) — pure headless rules logic that runs Lua card scripts and emits a binary duel-message stream; renders nothing. Built to "power server technologies."
- **Rulings content (reusable, must not re-invent):** `ProjectIgnis/CardScripts` (per-card Lua) + `cards.cdb` (SQLite: `datas` = stats bitfields, `texts` = name/effect; **no images**) + `lflist.conf` banlists.
- **Images:** separate, keyed by passcode; bulk-pull from the **YGOPRODeck API** (free, no key, 20 req/s, must self-host — no hotlinking) and store locally.
- **Reuse is proven:** `neos-ts` (production TS/React/WASM browser client over this engine), `EDOpro-server-ts` (TS WebSocket server pulling CardScripts+cdb+LFLists) — near-exact templates. A WASM build exists (`n1xx1/ocgcore-wasm`).
- **Interface:** the engine is callback-driven (`OCG_CreateDuel/StartDuel/DuelProcess/DuelGetMessage/DuelSetResponse`); we define our **own** JSON/WebSocket contract (no need to speak CTOS/STOC).
- **Edison filtering:** feasible via release-date + banlist + (most robust) a **frozen passcode allow-list** built once and founder-signed-off.
- **Licensing:** the edo9300 core + CardScripts are **AGPL-3.0** — negligible burden for a private/self-hosted app; precludes a future closed-source commercial product. YGOPRODeck: store data + self-host images. Konami IP: standard unlicensed-fan-work footing; low practical risk while private, a conscious decision if ever public.
- **Architecture options (CTO decision):** (A) native core on a server, browser↔server over WebSockets, **authoritative server-side state** — recommended for remote hidden-info play; (B) WASM core in-browser — reserve for offline/goldfish/AI-practice. Tradeoffs in §8 of the deep dive.

## 4. Accuracy linchpin — can the engine do *real* Edison rules? (R1)
*Deep dive: `engine-edison-rules.md` (engine source cited file:line).*

**Yes.** The **edo9300** fork split the historical Master Rules into independently-settable flags, so era rules are a first-class feature — **not** "the 2010 banlist on modern mechanics." Set them via `duelFlags` on `OCG_CreateDuel` (server-authoritative; the banlist file carries no rule directive). Findings:
- **Ignition priority** ✅ (`DUEL_TCG_FAST_EFFECT_IGNITION` — use the TCG flag so GY effects get priority too).
- **First-turn draw** ✅ (`DUEL_1ST_TURN_DRAW`). **Single Field Spell** ✅ (`DUEL_1_FACEUP_FIELD`).
- **Pre-2014 damage step** 🟡 flags exist (GOAT preset) — compose a custom set + validate (Spike A).
- **Card-level errata** 🟠 **MEDIUM residual risk:** shipped scripts use *modern* errata (verified: Brionac has an incorrect hard once-per-turn for Edison). The full list is now enumerated — **36 functional-errata entries** (`…-research-edison-functional-errata.md`): **6** have ready community substitutes (Brionac→511002993, Sangan, Rescue Cat, Goyo, Brain Control, Future Fusion), **6 more** have unused Edison-correct `pre-errata/` scripts, **~20** need audit/authoring, **5** are rules-not-scripts (engine flags). **Biggest gap: Red-Eyes Darkness Metal Dragon** — its shipped pre-errata script still enforces once-per-**name** and must be authored. Sources: `ThaSMorato/alt-formarts-lflists` (pool whitelist) + `diamonddudetcg` `Edison` git tag (errata substitutions); the `pre-errata/` folder is **not uniformly Edison-correct** — inspect each. Precedent: Dueling Nexus ships MR1 + March-2010 banlist + pre-errata. Our work is curation + a documented gap list, not invention.
- **Use the edo9300 fork** (the MIT Fluorohydride core lacks these granular flags).

**Bottom line:** "accuracy is sacred" is honorable — rules out of the box (with the right flag set), card text with ongoing curation and a small documented residual. We can be as accurate as, or better than, any automated sim.

## 5. Competitive UX landscape & our wedge
*Deep dive: `…-research-ux-landscape.md`.*

- **Master Duel:** polished, enforcing — but **modern-only**, heavy native download; only recently (mid-2025) added hints for why an effect can't activate.
- **Duelingbook:** the Edison community's home, but **manual/honor-system** and dated (3rd-party UI-fix extensions exist).
- **EDOPro:** the accurate enforcing engine we're reusing — **the complaint is the UI**, not correctness. Rated by the Edison community as imperfect on card errata out of the box (which our curation addresses).
- **Dueling Nexus:** closest shape (browser, enforcing, mobile-supported, strong deck builder) — we differentiate on **design quality, Edison focus, mobile-first**.
- **YGO Omega / edisonformat.net builder:** client-style / desktop-only (the Edison-native builder explicitly refuses mobile).
- **The gap we own:** polished + enforcing + Edison + genuinely good on mobile — none of them occupy it. UX principles carried into the build: surface legal actions; answer whose-turn/score/what-now at a glance; one tap-first interaction grammar across devices; "your-field-first" mobile board; slow, legible chain/priority resolution.

## 6. Key risks (carried into the handoff)

1. **Card-errata curation** (§4) — required workstream; without it ~3 dozen format-relevant cards are wrong (some meta-defining).
2. **Hidden-information leakage** — especially on reconnect and legitimate reveal effects; hard requirement regardless of architecture (WASM-in-browser makes it materially harder).
3. **Damage-step flag exactness** — validate the composed flag set against 2010 rulings (Spike A).
4. **Boundary discipline** ("enforce, don't explain") — surface legal options and response windows without shipping any "why-not" text.
5. **`.ydk` illegal/foreign import**, **alias copy-limit evasion**, **deck-out timing** — classic correctness traps enumerated in the requirements.
