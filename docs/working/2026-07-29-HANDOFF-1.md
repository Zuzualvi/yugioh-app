replaced two live screens with placeholders and deleted the endpoints their replacements had not
shipped yet; merging S0+S1 alone would still leave a user able to create a room and then hit 501s on
deck pick and ready. A half-built room is worse than an absent screen. So all slices land on
`integration/duel-room` and it merges to `master` once whole.

`ci.yml`'s `pull_request.branches` is an **allowlist** and was widened to include
`integration/duel-room` (commit `5d32826`, via the gated GitHub MCP — workflow files cannot be
changed by `git push`). A PR into a branch not named there runs **zero checks**, silently.

## 3. In flight — the one thing between here and the cutover

**`fix/room-snapshot-deck-info` @ `32ab70d` needs a PR and a merge.**

The defect: `deckInfo` was an **optional** 6th parameter to `buildRoomSnapshot`. Only `ready.ts` and
`pickDeck` passed it; `getRoomSnapshot` and `roomBroadcast` omitted it and silently received nulls.
A player who picked a deck or readied lost their own deck name and card count on the next snapshot —
every refresh, every reconnect, every frame caused by the opponent. That breaks R12 (a snapshot is the
**complete** state re-sent on every change and reconnect), R13/R6 (operable by polling, reconstructible
from the row) and E16/E37 (a refresh restores an identical room).

QA classified it "not a defect, consistent with the nullable spec". **I overruled that.** Nullable
means "no deck picked", not "picked, but this code path didn't look it up". The proposed mitigation —
the UI retains it from mutation responses — is client-only state that dies on reload, i.e. the ZUH-21
bug class, which this feature had already tried twice (the D5b login copy, the seat token).

The fix makes the parameter **required** so the compiler enforces it, with `loadRoomView` resolving
deck info for both occupants and `broadcastRoom` taking the whole `RoomView`. 12 files + 2 test files.
Engineer reports `npm run verify` green, 69 files / 1119 tests — **implementer-reported, not
independently verified.**

**Exact next actions:**

1. The CEO was asked to open the PR by hand (branch `fix/room-snapshot-deck-info` → base
   `integration/duel-room`, label `no-linear`, no `ZUH-` key in title or body). **UNVERIFIED whether
   that PR now exists** — check before doing anything.
2. A QA verification of `32ab70d` was dispatched and **its result had not arrived when this session
   ended.** If it arrives in your session, it was asked to confirm specifically: own deck name/count on

1. **Spawned specialists clone `/workspace/yugioh-app`, whose `origin` is a local directory.** Their
   pushes go nowhere and AGENTS.md's `remote == local` check **passes anyway** because it compares
   against that local repo. All three engineers hit this; I recovered every branch by hand with

   agent the explicit clone URL** `https://github.com/Zuzualvi/yugioh-app.git` and have it verify against
   that URL, not `origin`. Filed as friction **ZUH-38**.
2. **The GitHub MCP write tools are unreliable.** `create_pull_request` crashed ~29 times; merges
   crashed 3 times. **Standing CEO instruction: never retry a crashed MCP write more than twice, then
   stop and tell the CEO exactly what you need and on which branch.** Reads are fine. `git` via bash is
   fine — I merged via `git merge --no-ff` + push three times, and GitHub still marks the PR merged
   because the head commits become reachable from the base (verified on PRs #8, #9, #10), so Linear's
   `Closes` transition still fires.
3. **Do not build in the shared checkout.** Two concurrent agents in `/workspace/yugioh-app` put one's
   spike files onto the other's branch, including a debug WebSocket endpoint that would have shipped to
   production, and left the spine's `index.ts` wired to the spike's handler so an acceptance criterion
   was unmet **behind a green build**. Filed as friction **ZUH-33**. AGENTS.md's git section was rewritten
   for one-checkout-per-writer (`0d94bea`).
4. **Scoped green is not green.** AGENTS.md previously told parallel writers to "gate on your own
   package(s)". That is deleted, with the reason recorded, because it is what let the spine ship green
   with its room socket entirely unattached to the running server.
5. **Freezing files pushes engineers into bypasses.** Three separate slices reached for a workaround —
   raw SQL outside the store (twice), a module-level `registerDuelStart` singleton, a dropped toast —
   every time a handler needed something its file's owner hadn't anticipated. In each case the
   constraint was wrong, not the code, and I widened ownership. If you run parallel slices again, name
   the seams and grant them up front.
6. **A test that cannot fail.** The deck-to-seat reorder test used identical deck JSON for both
   players, so a swap — each player handed the other's deck, engine starts happily, nothing downstream
   notices — was undetectable. QA caught it. When a test asserts a mapping, check it can fail in both
   directions.
7. **`you.deckName` legitimately appears in snapshot JSON.** A future check for a deck-name leak must
   inspect `snapshot.opponent`, not grep the raw string. There is a comment at the assertion saying so.

## 6. Decisions made this session and why (do not silently reverse)

- **Room as its own table** sharing the duel's PK, rather than relaxing five `NOT NULL` columns on
  `duel`. R2's letter amended (absent, not NULL); its intent strengthened to a schema guarantee.
  ADR 0002.
- **Three enforced shapes**, which are the codebase standard for this module: the first write of every
  transition is a guarded `UPDATE … WHERE id = ? AND <expected state>` whose `changes === 1` decides;
  every read and mutation begins with the same `evaluateExpiry` writeback (no sweeper); every outbound
  payload comes from one `buildRoomSnapshot`. Amended after review to say explicitly that follow-up
  statements inside the same `db.transaction` may address the row by id — the defect the rule prevents
  is a read-then-write spanning a handler with no transaction.
- **Room socket rejects with HTTP 403 before the upgrade** for all three failure modes (bad `Origin`,
  no session, non-occupant), replacing close code `4403`. Refusing the handshake is stricter than
  completing it to close it.
- **`failStartingRoom`** as a separately named store function for T10, rather than a `reason`-dependent
  flag on `closeRoom` — whose Leave-is-final guard must stay exact.
- **`DuelManager` and the catalog are injected**, not fetched from module singletons.
- **`LoginScreen` fetches the challenger's name** via the unauthenticated lookup rather than receiving
  it in router state (spec §6.1).
- **No user-facing capability regresses** is now a standing delivery rule in AGENTS.md. It was added
  because a slice was verified 13/13 and recommended for merge while reducing two live screens to
  placeholders — every criterion met, and not one asked whether the product still worked.
- Inherited v1 spec amended where superseded: REQ-ROOM-01/02/05/07, REQ-LOBBY-05/06, REQ-DECK-16,
  REQ-TIMER-02.
