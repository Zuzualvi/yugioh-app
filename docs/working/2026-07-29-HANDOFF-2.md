## 2. NOT DONE — the two that matter, both the same root cause

### 2a. Three server wirings exist and must collapse onto `createApp()`

**This is the root cause of today's outage and it is still there.** Three files wire the Express app:

- `packages/server/src/app.ts` — what the **tests** exercise (via `createApp()`)
- `prod-server.ts` at the repo root — what **ships** (bundled by esbuild in the `Dockerfile`)
- `e2e/harness/server.ts` — what **E2E** runs

**All three had the same defect within one day.** The harness was missing `attachUpgradeRouter` and
silently dropped every WS upgrade (fixed in `87984ed`). `prod-server.ts` was missing both the room
router and the upgrade dispatcher (fixed in `b532363`). Only `app.ts` was correct, and it is the one
nothing deploys.

Consequence, stated plainly because it is the lesson of the day: **1181 unit tests, a 53/53
acceptance suite, 6/6 Playwright and an independent QA pass on a clean clone were all green while
production was broken.** Every gate we own passed. None of them executes the file that ships.

The fix is for `prod-server.ts` to call `createApp()` so one wiring exists. Its own PR, its own QA
pass. Note it is not a pure refactor: `prod-server.ts` also serves `/images` from the Fly volume,
does `bootstrapAdmin`, loads the catalog from an image-relative path and has its own env handling, so
the consolidation has to keep those. Read it before assuming it is a five-line change.

### 2b. `prod-server.ts` is in no tsconfig include

**OBSERVED:** `grep -n "prod-server" tsconfig*.json` finds nothing; only `package.json` references
it, as a `build:server` esbuild target. So `npm run typecheck` **never checks the file that ships**,
and esbuild only bundles — it does not typecheck. This is why the wiring could drift with every gate
green, and it is the mechanical hole behind 2a rather than a footnote to it.

Fixing this is likely a prerequisite for trusting 2a. Doing it will probably surface real errors that
have accumulated unchecked; budget for that rather than assuming it is a one-line `include`.

  What I *can* tell you, **OBSERVED**: the room socket now correctly distinguishes its failure modes

## 4. Warnings — each one cost real time today

1. **VERIFY AGAINST THE ARTIFACT, NOT AGAINST CI.** This is the whole lesson. CI cannot see
   `prod-server.ts`. To check a backend change actually works: bundle it with the `Dockerfile`'s
   exact esbuild invocation, stage the catalog with
   `mkdir -p dist/packages/card-data/out && cp packages/card-data/out/edison-card-catalog.json dist/packages/card-data/out/`,
   boot it with `DB_PATH=... PORT=... IMAGES_PATH=... NODE_ENV=production node dist/server.mjs`, and
   probe it. Better still, probe `api.zuhayr.io` after deploying. An A/B against the pre-fix bundle is
   what turns a plausible diagnosis into a confirmed one — my pre-fix column reproduced production's
   responses exactly, which is the only reason I trusted it.

2. **`curl` over HTTPS negotiates HTTP/2, where `Upgrade` is meaningless — always pass `--http1.1`
   when probing a WebSocket.** My first production WS probe returned `401` and looked exactly like a
   dead dispatcher on a fix that had just merged. It was my own test method. Local probes used plain
   HTTP so they never showed it. I nearly reported a working fix as broken.

3. **The Vercel Hobby author gate — read ADR 0003 before touching the deploy.** On a Hobby team a
   deployment is rejected unless the git commit author's email is the team owner's registered
   address; the CLI attaches git metadata from the checkout even for token deploys. It is refused
   *before the build is queued*, so the symptom is a job timeout with no build log, and the cause is
   an authorization refusal. This burned two sessions with two different wrong theories, mine
   included. `a1e00f6` removes the dependency entirely by deleting `.git`. **Do not delete that step**
   — and note that Vercel deployments consequently carry no commit SHA, so "what is live?" is
   answered from the Actions run, not the Vercel dashboard.

4. **`read_ci_status` attaches a stale historical failure log to every call**, with nothing marking it
   as not-current. A fault fixed hours ago reads as permanently live. Filed as ZUH-44. Read the
   provider's own records instead — the Vercel and Fly APIs — when the answer matters. Every fact
   needed to solve the author gate was in the Vercel deployments API the whole time.

5. **Fly "DEPLOYED" is the app's state, not proof the latest image was released.** It reads identically
   either way. I reported the cutover deployed on the strength of it. Probe a route that only exists in
   the new build instead.

6. **Workflow files cannot be changed by `git push`** — the push token lacks the Workflows permission,
   so they go through the gated GitHub MCP write. **Standing CEO instruction: write them to a BRANCH
   and open a PR, never straight to `master`.** `0ac8ea9` went directly to `master` with no PR, no CI
   and no review, and it carried a wrong root cause. **OBSERVED and useful:** once the workflow blob
   exists on the remote on a branch, a `git merge --no-ff` + `git push origin master` of that branch
   *does* succeed — so the full branch → PR → merge path works without needing the CEO to merge. Filed
   the underlying gap as ZUH-45.

7. **`ci.yml` and `e2e.yml` `pull_request.branches` are ALLOWLISTS.** A PR into a branch not named
   there runs **zero** checks and fails silently, because a PR with no checks looks much like a PR with
   passing ones. `e2e.yml` now covers `master` and `integration/*` (glob, so a future integration
   branch is automatic). This was the bug that hid the E2E mismatch for the whole build.

8. **An integration branch gets no CI on its own merge commits** — `ci.yml` is PR-triggered only, so
   merging a PR *into* `integration/duel-room` produces no run on that branch. Verify the integration
   head directly before a cutover.

9. **Never put a Linear key in a PR body for ticketless work — use the `no-linear` label.** A
   discovery issue (ZUH-24) was knocked out of *Done* twice in two days by PRs referencing it. Damage
   happens when the PR **opens**, not on merge. The CEO diagnosed the cause as the PR tool requiring a
   closing keyword, which pushes an agent to invent a plausible-looking key; that is being fixed. Filed
   as ZUH-48. **This applies to repair PRs only** — a normal slice PR should still carry
   `Closes ZUH-nn` for the issue it actually implements.

10. **Give spawned agents the explicit clone URL** `https://github.com/Zuzualvi/yugioh-app.git` and
    have them verify `git remote -v` shows github.com. Agents have previously cloned a local directory
    whose `remote == local` check passed against the wrong remote, and their pushes went nowhere.
    One clone per agent — two agents in one checkout has already put one's spike files on the other's
    branch. Filed as ZUH-38 / ZUH-33.

11. **Specialists misreport their own numbers.** An engineer reported "2817 pre-existing typecheck
    errors" (there are zero via the workspace scripts — it is a bare `npx tsc` at the root missing the
    `jsx` setting that only `packages/web/tsconfig.json` carries), a test count of 1361 against an
    actual 1181, and a PR as open that was closed. None of it changed the work, but check counts
    yourself before repeating them.

## 6. Decisions and where the reasoning lives

- `docs/adr/0002-room-as-its-own-table.md` — the room is its own table sharing the duel's primary key;
  the `duel` row is not created until seat assignment.
- `docs/adr/0003-deploy-deletes-git-before-vercel.md` — why `deploy-frontend` deletes `.git`, the
  20-deployment evidence, the alternatives (including why a Pro upgrade would *not* have fixed it),
  and both wrong theories.
- Three enforced shapes remain the codebase standard for the room module: the first write of every
  transition is a guarded `UPDATE … WHERE id = ? AND <expected state>` whose `changes === 1` decides;
  every read and mutation begins with the same `evaluateExpiry` writeback, so there is no sweeper;
  every outbound payload comes from one `buildRoomSnapshot`.
- Open friction filed today, all awaiting CEO triage: **ZUH-42** (no `FLY_API_TOKEN` for agents — this
  blocked the one check I could not do), **ZUH-44** (stale CI log), **ZUH-45** (workflow writes bypass
  PR/CI/review), **ZUH-48** (discovery-issue linking), **ZUH-49** / **ZUH-50** (from specialists).
