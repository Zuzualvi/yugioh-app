# Deploy Guide — Yu-Gi-Oh Edison on Fly.io

**Status:** Container verified locally. Awaiting Fly token from CEO.  
**Target:** Single always-on Machine on Fly.io (`*.fly.dev` HTTPS)  
**Architecture:** One Express process serves the React SPA + REST API + card images, same-origin.

---

## 1. CEO One-Time Account Setup

These steps are done ONCE by whoever owns the Fly.io account (the CEO):

1. **Create a Fly.io account** at <https://fly.io> and add a payment method.  
   Expected cost: ~$8–15/mo (1 shared CPU / 1 GB RAM Machine + 3 GB volume + IPv4).

2. **Install the `fly` CLI:**
   ```bash
   curl -L https://fly.io/install.sh | sh
   fly auth login
   ```

3. **Create a deploy token** (for the CI/CD pipeline or the CTO):
   ```bash
   fly tokens create deploy --name yugioh-app-deploy
   ```
   
   ⚠️ **Provide the token via a SECURE channel** (1Password shared vault, encrypted DM, or similar).  
   **NEVER** share it in chat, email, or commit it to git.

4. **Set the deploy token in your environment** (on the machine running `fly deploy`):
   ```bash
   export FLY_API_TOKEN=<token-from-step-3>
   ```

## 2. First Deploy (run once, in order)

### 2a. Choose app name and region

Edit `fly.toml` — update `app` and `primary_region` if desired:
```toml
app            = "yugioh-edison"   # becomes yugioh-edison.fly.dev
primary_region = "ord"             # Chicago; or: iad (Ashburn), lhr (London), etc.
```

### 2b. Register the app
```bash
cd /path/to/yugioh-app
fly launch --no-deploy -a yugioh-edison
# Answer prompts; say NO to creating a postgres DB.
```

### 2c. Create the persistent volume
```bash
fly volumes create yugioh_data \
  --size 3 \
  --region ord \
  -a yugioh-edison
```
> 3 GB is enough for the SQLite DB + all card images (~500 MB). Expand later with `fly volumes extend`.

### 2d. Set secrets (admin bootstrap credentials)

Choose a strong username and password for the first admin account.  
These are set as **Fly secrets** — they are encrypted at rest and never appear in logs or config files.

```bash
fly secrets set \
  BOOTSTRAP_ADMIN_USERNAME=your_admin_username \
  BOOTSTRAP_ADMIN_PASSWORD='YourStr0ng!Password' \
  -a yugioh-edison
```

> `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` are consumed once at startup: if no admin exists yet, the first admin user is created. On subsequent restarts they are ignored (idempotent). You can unset them after bootstrap if desired:
> ```bash
> fly secrets unset BOOTSTRAP_ADMIN_USERNAME BOOTSTRAP_ADMIN_PASSWORD -a yugioh-edison
> ```

### 2e. Deploy
```bash
fly deploy -a yugioh-edison
```

Fly builds the Docker image (or uses the local build), pushes it, and starts the Machine.  
Watch logs:
```bash
fly logs -a yugioh-edison
```

Expected startup log lines:
```
[prod-server] Catalog loaded: 3681 cards
Yu-Gi-Oh server listening on port 8080 (NODE_ENV=production)
[bootstrap] Created admin user "your_admin_username" (id=...)
```

### 2f. Verify the live deploy
```bash
curl https://yugioh-edison.fly.dev/healthz
# → {"status":"ok","cards":3681}

curl -s "https://yugioh-edison.fly.dev/api/cards?pageSize=1" | python3 -m json.tool | grep total
# → "total": 3681
```

## 3. Subsequent Deploys (team)

After the first deploy, any team member with the Fly token can redeploy:
```bash
export FLY_API_TOKEN=<your-token>
fly deploy -a yugioh-edison
```

Or set up GitHub Actions CI using the token as a repository secret (`FLY_API_TOKEN`).

## 4. Admin Bootstrap

**How it works:**  
On server startup, if `BOOTSTRAP_ADMIN_USERNAME` + `BOOTSTRAP_ADMIN_PASSWORD` env vars are set AND no admin user exists yet in the DB, one admin account is created. This is idempotent — it never overwrites an existing admin.

**After bootstrap:**
- Log in at `https://yugioh-edison.fly.dev/` with the credentials you set.
- Use the admin panel to create invite codes for other users.
- Optionally unset the bootstrap secrets (they become a no-op once an admin exists).

## 5. Image Seed (after first deploy)

Card images (~3,681 files, ~500 MB) are downloaded to the volume from YGOPRODeck.  
This is a one-time step after the first deploy (or on a fresh volume).

```bash
# Option A: run the seed inside the Machine via SSH
fly ssh console -a yugioh-edison -C "node /app/deploy/seed-images.mjs"

# Option B: use the wrapper script
bash deploy/seed-images.sh yugioh-edison
```

The script is idempotent (skips images already present) and rate-limited to ≤20 req/s.

> **Note:** The web frontend currently hotlinks card images from the YGOPRODeck CDN.  
> The `/images/<imageId>.jpg` route on the server is ready for when the frontend switches  
> to use self-hosted images (a future spec). Seeding now ensures images are available  
> when that switch happens.

## 6. Backup

See `deploy/backup.md` for full details.

- **Automatic:** Fly.io takes daily volume snapshots (5-day retention by default).
- **Manual dump:**
  ```bash
  fly ssh console -a yugioh-edison
  sqlite3 /data/yugioh.db ".backup /data/yugioh-backup-$(date +%Y%m%d).db"
  ```

## 7. Custom Domain (later)

When you're ready to add a custom domain:

```bash
# 1. Add the domain to Fly
fly certs add yourdomain.com -a yugioh-edison

# 2. Fly shows the required DNS records (CNAME or A). Add them to your DNS provider.

# 3. Wait for TLS certificate (usually 1–2 minutes)
fly certs check yourdomain.com -a yugioh-edison
```

Fly issues a free Let's Encrypt certificate automatically.  
`force_https = true` in `fly.toml` ensures HTTP redirects to HTTPS for the custom domain too.

## 8. Scaling

The Machine is configured with:
- `min_machines_running = 1` — always-on (required for wall-clock timers in the dueling slice)
- `auto_stop_machines = false` — never sleeps
- 1 shared CPU / 1 GB RAM

To increase memory if needed:
```bash
fly machine update <machine-id> --memory 2048 -a yugioh-edison
# or edit fly.toml → [vm] memory = "2gb" → fly deploy
```
