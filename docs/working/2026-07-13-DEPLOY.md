# Deploy Guide — Yu-Gi-Oh Edison (Vercel + Fly.io split)

**Status:** Awaiting `provision_hosting` by CTO (requires CEO account approval).  
**Architecture:** Vercel serves the React SPA (`app.<domain>`); Fly.io serves the API + card images
(`api.<domain>`). Same registrable domain → same-site cross-origin; `SameSite=Lax` cookies flow
correctly; CORS allowlist enforces origin isolation.

---

## Overview of the deploy flow

```
provision_hosting
   └─ creates:  Fly app + volume + deploy token
                Vercel project + domain/DNS wiring
                GitHub repo secrets (FLY_API_TOKEN, VERCEL_TOKEN, ...)
CTO commits .github/workflows/deploy.yml
   └─ merge to master = deploy (Fly + Vercel in parallel)
CTO sets Fly secrets (admin bootstrap creds)
CTO sets Vercel project env vars (VITE_API_BASE_URL, VITE_IMAGE_BASE_URL)
First merge → deploy fires → post-deploy image seed
```

---

## 1. `provision_hosting` (CTO — requires CEO approval for paid resources)

`provision_hosting` is the automated provisioning tool that creates all paid infrastructure.
It requires CEO sign-off before running (Fly.io and Vercel both have billing).

What it provisions:
- **Fly.io**: app registration, `yugioh_data` volume (3 GB), deploy token
- **Vercel**: project linked to this repo, custom domains (`app.<domain>`, `api.<domain>` alias)
- **DNS**: `app.<domain>` → Vercel, `api.<domain>` → Fly app
- **GitHub repo secrets**: `FLY_API_TOKEN`, `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`

After `provision_hosting` completes, update `fly.toml`:
- Set `app` to the provisioned Fly app name
- Replace `PLACEHOLDER_DOMAIN` in `CORS_ALLOWED_ORIGINS` with the real domain

---

## 2. CTO commits the deploy workflow

Commit `.github/workflows/deploy.yml` to the repo. Merge to `master` triggers a deploy:
- Fly: `fly deploy` (builds the API-only Docker image, pushes, restarts the Machine)
- Vercel: Vercel's GitHub integration builds and deploys the SPA automatically

The deploy workflow also forwards admin bootstrap secrets to Fly on the first deploy (see §3).

---

## 3. Admin bootstrap (first deploy only)

The bootstrap secrets are stored as **GitHub repo secrets** (`BOOTSTRAP_ADMIN_USERNAME`,
`BOOTSTRAP_ADMIN_PASSWORD`) and forwarded to Fly by the deploy workflow:

```bash
flyctl secrets set \
  BOOTSTRAP_ADMIN_USERNAME="$BOOTSTRAP_ADMIN_USERNAME" \
  BOOTSTRAP_ADMIN_PASSWORD="$BOOTSTRAP_ADMIN_PASSWORD" \
  --stage \
  -a <fly-app-name>
```

**How it works:** On server startup, if `BOOTSTRAP_ADMIN_USERNAME` + `BOOTSTRAP_ADMIN_PASSWORD`
are set and no admin exists in the DB yet, one admin account is created. Idempotent — never
overwrites an existing admin. The secrets can be unset from Fly after the first successful
bootstrap:

```bash
flyctl secrets unset BOOTSTRAP_ADMIN_USERNAME BOOTSTRAP_ADMIN_PASSWORD -a <fly-app-name>
```

## 4. Vercel project environment variables

Set in the Vercel project dashboard (or via Vercel CLI) for the **Production** environment:

| Variable              | Value                              |
|-----------------------|------------------------------------|
| `VITE_API_BASE_URL`   | `https://api.<domain>`             |
| `VITE_IMAGE_BASE_URL` | `https://api.<domain>/images`      |

These are baked into the SPA bundle at Vercel build time. Without them the prod bundle will not
point at the Fly backend.

`packages/web/vercel.json` configures Vercel (Root Directory = `packages/web`) to install and
build from the **repo root** so that the `@yugioh-app/contracts` workspace symlink resolves:
- `installCommand`: `cd ../.. && npm install`
- `buildCommand`: `cd ../.. && npm run build:web`
- `outputDirectory`: `dist`

## 5. Post-deploy: image seed

Card images (~3,681 files, ~500 MB) are stored on the Fly volume (`/data/images`). Seed them
once after the first deploy (the seed script is idempotent — skips images already present):

```bash
# Option A: via Fly SSH
fly ssh console -a <fly-app-name> -C "node /app/deploy/seed-images.mjs"

# Option B: wrapper script
bash deploy/seed-images.sh <fly-app-name>
```

Re-run after replacing the volume if it is ever wiped.

## 6. Local Docker verify

Run the API-only image locally to confirm everything works before pushing:

```bash
# 1. Build the server bundle
npm run build:server

# 2. Build the Docker image
docker build -t yugioh-api-local .

# 3. Run with a fixture DB (ALLOW_FIXTURE_CATALOG uses the baked-in catalog; no volume needed)
docker run --rm -p 8080:8080 \
  -e ALLOW_FIXTURE_CATALOG=1 \
  -e CORS_ALLOWED_ORIGINS=https://app.example.com \
  -e BOOTSTRAP_ADMIN_USERNAME=admin \
  -e BOOTSTRAP_ADMIN_PASSWORD=password123 \
  yugioh-api-local

# 4. Verify in another terminal
curl http://localhost:8080/healthz
# → {"status":"ok","cards":3681}

curl http://localhost:8080/
# → {"service":"yugioh-edison-api"}

# 5. CORS preflight
curl -si -X OPTIONS http://localhost:8080/api/cards \
  -H "Origin: https://app.example.com" \
  -H "Access-Control-Request-Method: GET" | grep -i "access-control"
# → Access-Control-Allow-Origin: https://app.example.com
# → Access-Control-Allow-Credentials: true

# 6. Login (sets SameSite=Lax cookie)
curl -si -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"password123"}' | grep -i "set-cookie"
# → Set-Cookie: ...; SameSite=Lax
```

## 7. Fly.toml placeholders (CTO action required post-provision)

After `provision_hosting`, update `fly.toml` in a follow-up commit:

```toml
app = "<provisioned-fly-app-name>"

[env]
  CORS_ALLOWED_ORIGINS = "https://app.<real-domain>"
```

Commit and push — the next deploy picks up the new CORS allowlist.

## 8. Backup

- **Automatic:** Fly.io takes daily volume snapshots (5-day retention by default).
- **Manual dump:**
  ```bash
  fly ssh console -a <fly-app-name>
  sqlite3 /data/yugioh.db ".backup /data/yugioh-backup-$(date +%Y%m%d).db"
  ```

See `deploy/backup.md` for full details.

## 9. Scaling

The Machine is configured with:
- `min_machines_running = 1` — always-on (required for wall-clock timers in the dueling slice)
- `auto_stop_machines = false` — never sleeps
- 1 shared CPU / 1 GB RAM

To increase memory:
```bash
fly machine update <machine-id> --memory 2048 -a <fly-app-name>
# or edit fly.toml → [vm] memory = "2gb" → fly deploy
```
